# Демо-данные ГДеволна 2.0 (`seed_demo`)

Посевные данные для dev/staging из прототипа v14 (`docs/prototype/frontend-port/seed_public.json`,
`seed_cabinet.json`, изображения из `frontend-port/assets` и `source/img`). Код — `backend/apps/demo/`
(`data.py` — сопоставленные данные, `seeding.py` — построение и удаление, `assets.py` — S3 и `MediaAsset`).
В прод демо-данные не выкладываются без явной маркировки (TZ §4): все записи помечены `is_demo=True`
(или принадлежат демо-аккаунтам у моделей без такого поля).

## Запуск

```bash
docker compose run --rm backend python manage.py seed_demo            # загрузить, если демо-данных ещё нет
docker compose run --rm backend python manage.py seed_demo --if-empty # ничего не делать, если есть демо-спот
docker compose run --rm backend python manage.py seed_demo --reset    # удалить демо-данные и создать заново
docker compose run --rm -e TEST_DB_NAME=test_demo backend pytest apps/demo --create-db
```

- При `SEED_DEMO=1` (по умолчанию в `docker-compose.yml`) entrypoint вызывает `seed_demo --if-empty` после миграций.
  В этом режиме ошибка посева (например, недоступен MinIO) печатается в лог, но не мешает старту сервера.
- Без флагов при уже загруженных данных команда ничего не меняет и подсказывает `--reset`.
- `--reset` удаляет в порядке зависимостей демо-аккаунты, демо-организации, демо-споты, модели досок, инвентарь,
  занятия, события клуба, анонсы демо-авторов, демо-товары — и всё, что от них зависит и было создано при ручной
  проверке (брони, обращения с диалогами, личные диалоги, отзывы демо-авторов, события аналитики демо-аккаунтов).
  Обычные (не демо) аккаунты не удаляются. Регионы — справочник, они обновляются, но не удаляются.
- Загрузка в S3 идёт до транзакции; удаление и создание записей в БД — в одной `transaction.atomic()`.
  Время занятий и событий считается от момента запуска, поэтому после `--reset` расписание снова «свежее».

## Изображения

Файлы скопированы в `backend/apps/demo/seed_assets/` (контейнер backend видит только `./backend`) и загружаются
в бакет `S3_BUCKET` под `public/seed/…` с WebP-миниатюрой `<key>.thumb.webp` (Pillow, ≤640 px). Для каждого
файла — `MediaAsset` (`status=ready`, `visibility=public`, `is_demo=True`, kind/purpose/width/height/size/
content_type/sha256). Повторный запуск идемпотентен по `storage_key`: объект с тем же sha256 не перезаливается,
строка `MediaAsset` переиспользуется (и после `--reset`). У каждого использования свой ключ, поэтому удаление фото
у одной модели через API не ломает другую. Пример: `http://localhost:8080/gdevolna-media/public/seed/spots/spot-olenevka-1.jpg`.

## Что намеренно НЕ загружается

| Не переносим | Почему |
|---|---|
| Отзывы (7 к инструкторам, 1 к шейперу), рейтинги и число отзывов спотов/инструкторов/мастерских | TZ 12.2, PL-02, BR-08, TRUST-01: рейтинг — только из опубликованных реальных отзывов; у всех демо-объектов `rating_avg = 0`, `rating_count = 0` |
| Сертификаты инструкторов («✓ сертификат · демо») | BR-07, INS-03, PL-02: значок «проверен» — только после модерации документа; у демо-инструкторов статус «не указан» |
| Обращения/заявки, переписки, входящие шейпера, сообщения чатов | TZ 12.2, PL-02, ATX-33 |
| Уведомления, события аналитики, статистика (просмотры, избранное, выручка, счётчики) | TZ 12.2, PL-02, раздел 10 (метрики считаются только из реальных событий) |
| Заявки на аренду, брони | синтетические записи прототипа (TZ 12.2) |
| Достижения клуба, клубная карточка «№ 001 · DEMO» | COM-09 (позже); текст «О нас и клуб» отдаётся приложением `club` статично |

Команда никогда не создаёт `Review`, `Inquiry`, `Conversation`, `Message`, `Notification`, `AnalyticsEvent`,
`Booking`, `InstructorCertificate` — это проверяется в `apps/demo/tests/test_seed.py`.

## Решения и что не удалось сопоставить один к одному

- **Иван Петров** — один аккаунт: инструктор (Камчатка) и шейпер мастерской «Kamchatka Boards» (в прототипе это
  «своя» мастерская демо-пользователя с тем же мастером и регионом). Демонстрирует несколько направлений у
  одного аккаунта. Код шейпера `KBA01` (в прототипе случайный `S?????`), у остальных — коды прототипа.
- **Споты:** «Озёрный спот» (Ладога) → `beach` + характер волны «Ветровая волна (озёрный спот)»; «Риф / пляж»
  (Оленевка) → `reef`; «Чёрный песок» → `sand`, «Песок и камни» → `mixed` (уточнение — в «Типичных условиях»).
  Ветер/свелл без направления («По прогнозу», «Тихоокеанский», «Охотское море») — пустые румбы, текст в типичных
  условиях. «Особенности места» (вулканы, котики…) — в описании, отдельного поля нет. «Подводные препятствия» и
  «лодочное движение» → код `other`, полный текст — в `hazard_notes`. «Подъезд», «Баня в регионе», «Машина
  необходима» → инфраструктура `other` с названием. «Вход/выход» и «Подъезд» в прототипе пусты — составлены из
  описания и типа дна (помечены «требует проверки на месте»). Точность координат: `exact` для Англичанки и
  Халактырского, `approximate` для округлённых.
- **Инструкторы:** споты прототипа, которых нет в каталоге (Авачинская бухта, Паратунка, Балаклава, Пильтун…),
  перечислены в «О себе»; профиль привязан к спотам каталога того же региона. Одно число «опыт N лет» заполняет
  `surfing_since` и `teaching_since`. Языки в прототипе не заданы — `ru`. Статус GG («Покажу споты», «Ищу компанию»,
  «Могу подвезти») сохранить некуда — в `UserProfile` нет поля (заполнится автоматически, если поле `gg_status`
  появится). Интересы и любимые споты GG-участников в прототипе не заданы — подобраны из списка интересов прототипа.
- **Доски:** у моделей Volna Craft, Baltic Surf Lab и «Сахалинских досок» в прототипе нет ширины, а `width_in`
  обязательна — указана типичная для типа (лонгборд 22¾″, фиш 20¾″, шортборд 19¼″, фанборд 21½″, SUP 32″),
  толщина пустая. Материал варианта — первый материал мастерской. «Стекловолокно», «Эпоксидная смола», «EPS / PU» —
  пользовательские материалы мастерских (в стандартном справочнике их нет), «Карбон» — стандартный.
- **Школа:** в прототипе демо-школы нет — собрана по примерам из кабинета (Kamchatka Surf School, «Первое знакомство
  с волной», длительность 90 мин, начало занятий 10:00); владелец, менеджер и тексты — вымышленные.
- **Прокат:** все 8 объявлений прототипа принадлежат одной организации; имя владельца из прототипа стало
  «выдаёт …» в месте получения. Цены — «пример цены» прототипа, только в демо-записях.
- **Магазин:** характеристики термосов — целевые, с пометкой «уточняется» (SHOP-04).
