# Эксплуатация

## Окружения (раздел 4.1)

| | dev (этот репозиторий) | staging / prod |
|---|---|---|
| Запуск | `docker compose up` (production-сборка) или `make dev` (`docker-compose.dev.yml`: монтирование исходников, `next dev`) | `docker compose -f docker-compose.yml up` или оркестратор; образы из CI |
| `APP_ENV` | `dev` | `staging` / `prod` (secure cookies, HSTS) |
| `DJANGO_DEBUG` | 1 | 0 |
| Секреты | значения по умолчанию из compose | только из секрет-хранилища (`DJANGO_SECRET_KEY`, пароли БД/брокера/S3) — никогда в репозитории |
| Демо-данные | `SEED_DEMO=1` | `SEED_DEMO=0`; в staging — только с явной маркировкой `is_demo` |
| TLS | нет | терминируется на балансировщике/nginx; `SITE_URL=https://…`, `DJANGO_CSRF_TRUSTED_ORIGINS` |
| Почта | Mailpit | реальный SMTP-провайдер (`EMAIL_HOST`, `EMAIL_PORT`) |
| S3 | MinIO в compose | управляемое S3-совместимое хранилище + CDN; публичный префикс `public/` читается анонимно, `private/` — только presigned |
| 2FA персонала | обязательна (`STAFF_2FA_REQUIRED=1`) | обязательна |

## Резервное копирование и восстановление (11, ATX-30)

Чек-лист тренировочного восстановления:
1. `make backup` — `pg_dump -Fc` в `./backups/gdevolna-<время>.dump`.
2. `make restore-check` — создаёт отдельную БД `restore_check`, восстанавливает дамп, сверяет число строк в ключевых
   таблицах (аккаунты, споты, организации, модели досок, обращения, брони, сообщения, отзывы, аудит) с рабочей БД
   и удаляет копию. Рабочая БД не меняется. Код возврата ≠ 0 при расхождении.
3. Медиа: включить версионирование бакета и репликацию на стороне S3-провайдера; в dev объекты MinIO лежат в томе
   `miniodata`.
4. Периодичность в prod — ежедневный дамп + WAL-архивирование (PITR); тренировка восстановления — ежемесячно.

## Наблюдаемость

- Каждый запрос получает `X-Request-ID` (nginx `$request_id` → Django → логи → тело ошибки API `request_id`).
- `GET /api/v1/health` — проверка БД и кеша (используется healthcheck-ом backend).
- Celery: RabbitMQ management UI (очереди, consumers); задачи с ретраями и экспоненциальной задержкой (email).
- Аудит действий модераторов/администраторов: `/moderation/audit` и `trust.AuditEvent` (только чтение в админке).

## Релиз и откат

1. Миграции обратно-совместимы (сначала добавить поле, затем код, затем удалить старое).
2. `docker compose run --rm backend python manage.py migrate` до переключения трафика.
3. Откат — предыдущий тег образа; откат миграций только при наличии обратной операции.
4. После деплоя — `make test-e2e` против staging (BASE_URL).
